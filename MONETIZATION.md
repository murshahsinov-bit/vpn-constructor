# Монетизация ShieldVPN

Документ описывает, как устроены продажи: тарифы, пробный период, выбор
устройства (Android / iPhone), активация по ссылке, оплата и что нужно сделать
при запуске. Технические детали деплоя — в [`DEPLOY_NETRUN.md`](DEPLOY_NETRUN.md),
инструкция для iOS — в [`HAPP_INCY.md`](HAPP_INCY.md).

## 1. Модель

| | |
| --- | --- |
| Продукт | VPN с обходом DPI для YouTube, автовыбором серверов |
| Пробный период | 3 дня, один раз на устройство (настраивается `TRIAL_DAYS`) |
| Тарифы | 149 ₽ / 349 ₽ / 990 ₽ за 1 / 3 / 12 месяцев |
| Ограничение трафика | триал — 10 ГиБ, платный — 250 ГиБ (`TRIAL_TOTAL_BYTES`, `PAID_TOTAL_BYTES`) |
| Оплата | Telegram Stars (XTR): без юрлица, эквайринга и модерации магазина |
| Устройства | Android — своё приложение, iPhone — Happ или INCY |

Цены заданы в одном месте: `netrun_worker/plans.py`. Сайт, бот и воркер читают
их оттуда (`GET /api/plans`), приложение показывает срок из лицензии.

## 2. Лицензия

Лицензия — самодостаточный подписанный токен:

```text
SVS1.<base64url(payload)>.<base64url(hmac_sha256)>
payload = {"v":1,"sub":"…","plan":"trial|m1|m3|m12","dev":"android|ios","iat":…,"exp":…}
```

- Воркер не хранит список выданных лицензий: подпись и срок проверяются
  локально, поэтому перезапуск контейнера ничего не ломает.
- Клиент не может продлить срок или сменить тариф: без `LICENSE_SECRET`
  подпись не подделать.
- `exp` — Unix-время окончания. Приложение считает остаток дней офлайн.
- Смена `LICENSE_SECRET` аннулирует все выданные лицензии.

Секрет знают только воркер и тот, кто выдаёт лицензии (бот получает их через
`/api/admin/issue`). В APK секрета нет.

## 3. Пробный период

```text
Приложение / бот → POST /api/trial {"device":"android","device_id":"android-…"}
                  → 200 + лицензия plan=trial, exp=+3 дня
                  → 409 trial_already_used
```

- Устройство идентифицируется случайным UUID, который приложение хранит в MMKV.
  Переустановка приложения сбрасывает UUID, но IP-лимит (5 выдач в сутки)
  отсекает массовый перебор.
- Учёт хранится в `data/trials.json` (`TRIAL_STORE`). На бесплатном Netrun файл
  может пропасть при пересоздании контейнера — см. `DEPLOY_NETRUN.md`, 11.5.
- В приложении триал запрашивается автоматически сразу после входа. Если он уже
  использован, открывается экран активации.

## 4. Пользовательские сценарии

### Android (своё приложение)

1. `/start` в боте → «Пробный период» → Android → ссылка активации.
   Либо «Купить подписку» → Android → тариф → счёт в Stars → ссылка.
2. Пользователь ставит APK, входит по e-mail или Google.
3. Приложение само пробует триал; если тот уже использован — показывает экран
   «Активация подписки».
4. Пользователь вставляет ссылку (или нажимает deep link
   `shieldvpn://activate?token=…`) → `POST /api/activate` → лицензия сохранена.
5. `GET /sub/auto_happ.txt?token=<лицензия>` → серверы → кнопка «Подключиться».

### iPhone / iPad (Happ или INCY)

1. Бот → «Пробный период» или «Купить» → iPhone → ссылка вида
   `https://vpn-auth.de1.netrun.io/sub/incy.txt?token=<лицензия>`.
2. Пользователь добавляет её в Happ/INCY как подписку.
3. `/sub/incy.txt` отдаёт только `VLESS + TCP + Reality + Vision` с
   фрагментацией `fragmentPackets=tlshello&fragmentLength=100-200&fragmentInterval=10-20`.

### Продление

Бот → «Купить подписку» → тариф → оплата → новая лицензия. Пользователь вводит
её на экране активации; старая ссылка подписки заменяется автоматически
(`subscriptionUrl` в MMKV обновляется при смене токена).

## 5. Оплата Stars

- `sendInvoice` с `currency: "XTR"` и без `provider_token`.
- В `payload` счёта: `v1|<plan>|<device>|<chat_id>`.
- После `successful_payment` бот вызывает `POST /api/admin/issue` и присылает
  лицензию. Номер платежа (`telegram_payment_charge_id`) сохраняется в
  `billing_bot/data/payments.json`, поэтому повторный апдейт не выдаст вторую
  лицензию.
- Возвратов в Stars нет: перед оплатой есть пробный период и понятные условия.

Цена в Stars считается как `ceil(price_rub / STAR_RUB_RATE)`. Курс вынесен в
переменную окружения: при изменении курса поменяйте её и перезапустите воркер.

## 6. Что где лежит

| Файл | Роль |
| --- | --- |
| `netrun_worker/plans.py` | Тарифы, цены в рублях и Stars, длина триала |
| `netrun_worker/licensing.py` | Подпись и проверка лицензий |
| `netrun_worker/trials.py` | Учёт выданных триалов (устройство + IP) |
| `netrun_worker/app.py` | `/api/plans`, `/api/license`, `/api/activate`, `/api/trial`, `/api/admin/issue`, `/activate/<lic>` |
| `billing_bot/core.py` | Тексты, клавиатуры, callback-и (без сети — покрыто тестами) |
| `billing_bot/handler.py` | Long polling, счета Stars, выдача лицензий |
| `billing_bot/worker_client.py` | HTTP-клиент воркера (без `LICENSE_SECRET`) |
| `site/index.html` | Лендинг: тарифы, выбор устройства, установка |
| `ShieldVPN/.../ShieldLicense.kt` | Хранение и активация лицензии в приложении |
| `ShieldVPN/.../ui/shield/ShieldActivity.kt` | Экран активации + бейдж «Пробный период · N дн.» |

## 7. Чек-лист запуска

1. Задать в Netrun: `LICENSE_SECRET`, `ADMIN_TOKEN`, `PUBLIC_BASE_URL`.
2. Загрузить `netrun-worker.zip` (в архиве уже есть `licensing.py`, `plans.py`,
   `trials.py`). Проверить `/api/plans` → 200 и `currency: RUB`.
3. Создать бота у @BotFather, включить Payments, задать `BOT_TOKEN` и
   `ADMIN_TOKEN`, запустить `billing_bot`.
4. Проверить сквозной сценарий: триал в боте → ссылка → активация в приложении
   → подписка загрузилась → VPN поднялся.
5. Проверить оплату в тестовом режиме Stars (или минимальным тарифом) и
   повторную доставку `successful_payment` (лицензия не должна выдаться дважды).
6. Опубликовать лендинг (`site/`): цены подтянутся с воркера, при недоступности
   останутся значения из HTML.
7. Обновить `BOT_URL` в `ShieldConfig.kt`, если username бота отличается от
   `shieldvpn_bot`, и пересобрать APK.

## 8. Ограничения и риски

- **Один аккаунт — одно устройство**: лицензия не привязана к железу, её можно
  передать. Для жёсткой привязки нужен HWID-учёт на воркере (следующий шаг).
- `data/trials.json` и `billing_bot/data/payments.json` — файлы. На нескольких
  инстансах нужен общий store (Redis/Postgres).
- Stars принимаются только в Telegram; для карт и СБП нужен эквайринг
  (ЮKassa/CloudPayments) и юрлицо.
- В приложении нет экрана управления подпиской: продление — через бота. Это
  осознанно: не требуется IAP и модерация Google Play.
