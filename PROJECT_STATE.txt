1. ЧТО ЭТО
--------------------------------------------------------------------------------
VPN-клиент на базе Xray-core (форк v2rayNG), пакет io.netrun.shieldvpn.
Подписка: VLESS + XHTTP + Reality (Android), TCP + Reality + Vision (iOS).
Локальный обход DPI: ciadpi (ByeDPI) на 127.0.0.1:1080, маршрутизация через
Xray outbound `byedpi` (youtube.com, googlevideo.com, ytimg.com, ggpht.com).
Бэкенд подписок: netrun_worker/app.py (Flask) + агрегатор aggregator/run.py.

5. АРХИТЕКТУРНЫЕ ЗАМЕТКИ
--------------------------------------------------------------------------------
- Подписка хранится в MMKV под ключом shield_default_subscription; при смене
  аккаунта URL перезаписывается и подписка перекачивается.
- `/sub/incy.txt` не создаёт отдельный файл: он фильтрует auto_all.txt на лету,
  поэтому всегда совпадает с общей подпиской.
- Авторизация `user` проверяет только формат (по требованию). Настоящая
  проверка Firebase ID Token — следующий шаг, нужен FIREBASE_PROJECT_ID и
  сервисный аккаунт; сейчас любой валидный по форме UID/e-mail получает 200.
- Legacy MainActivity/AboutActivity/Drawer остались в коде для QS tile, но из
  UI ShieldVPN недоступны.
- Домен панели подписки всегда идёт через outbound `direct`
  (ShieldDirectRouting, правило вставляется первым). Это не зависит от ByeDPI:
  правило добавляется в любой сгенерированный конфиг.

5a. РЕКОМЕНДАЦИИ ПО ИТОГАМ АУДИТА
--------------------------------------------------------------------------------
1. Безопасность подписки (важно): воркер проверяет только формат `user`,
   поэтому любой валидный UID/e-mail получает список серверов. Следующий шаг —
   проверка Firebase ID Token (`Authorization: Bearer <idToken>`) через
   сервисный аккаунт проекта, с сохранением `user` как fallback на переходный
   период. Нужны FIREBASE_PROJECT_ID и сервисный JSON в переменных Netrun.
2. Наследие v2rayNG в маршрутизации: ассеты app/src/main/assets/custom_routing_*
   содержат китайские названия правил, они видны на экране «Маршрутизация».
   Стоит заменить на 2–3 пресета ShieldVPN на русском (Обход LAN, YouTube через
   ByeDPI, всё через VLESS) и не тянуть китайские списки в новый профиль.
3. ByeDPI: README hufrea/byedpi рекомендует `--timeout 3` вместе с
   `--auto=torst` (у нас 5 — фолбэк медленнее). Если DPI упорствует, добавить
   `--tlsrec 3+s` второй группой после `--auto=torst`.
4. Не запускались проверки: TalkBack для диалога темы, динамический цвет,
   D-pad/клавиатурная навигация по диалогу (по гайду UI это «Not run»).
5. Нет instrumentation-теста на connect-flow (VPN/Reality); JVM-тесты покрывают
   только чистую логику (маршрутизация, результат обновления).
